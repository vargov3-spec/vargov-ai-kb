# Передача задачи агенту на рабочем компьютере

Этот файл — вводная для ИИ-агента, который продолжит работу на рабочей машине владельца. Контекста у него нет, поэтому здесь всё с нуля.

Дата подготовки: 2026-08-09.

---

## 1. Кто и что

Vargov®Design — производитель авторских световых и декоративных композиций. Сайт: **vargov.ru**, приложение на Next.js.

Есть два репозитория на GitHub, аккаунт `vargov3-spec`:

| Репозиторий | Что это |
|---|---|
| `vargov-ai-kb` (публичный) | База знаний: тексты, переводы, данные для интеграции. **Этот репозиторий.** |
| `vargov-configurator` (приватный) | Конфигуратор композиций, отдельное приложение |

**Кода самого сайта на GitHub нет.** Он лежит только на рабочем компьютере владельца — том, за которым вы сейчас работаете. Это и есть главная задача.

## 3. Главная задача: выгрузить код сайта в GitHub

Сейчас код сайта существует в единственном экземпляре, без истории и без резервной копии. На сервере лежит только собранная версия (`/var/www/vargov/ru/` — `server.js`, `.next`, `node_modules`), исходников там нет.

### Шаг 1. Найти папку проекта

Это Next.js-проект. Признаки: файлы `next.config.js` (или `.mjs`/`.ts`), `package.json` с зависимостью `next`, папки `app/` или `pages/`. Владелец подскажет путь; ранее в документации встречался диск `V:\`.

### Шаг 2. Проверить, не репозиторий ли уже

```bash
cd <путь к проекту>
git remote -v
git log --oneline -5
```

Если `git remote -v` что-то выводит — код уже привязан к какому-то хранилищу. **Остановитесь и сообщите владельцу адрес**, дальше решать ему.

### Шаг 3. Создать `.gitignore` ДО первого коммита

Критично. Без этого в публичный доступ уедут пароли и ключи.

```
node_modules/
.next/
out/
build/
dist/

.env
.env.*
!.env.example

*.log
.DS_Store
Thumbs.db
.vercel
next-env.d.ts
```

### Шаг 4. Первый коммит и публикация

```bash
git init -b main
git add .
git status          # ОБЯЗАТЕЛЬНО проверить глазами
```

**Перед коммитом убедитесь, что в списке нет:** `node_modules`, `.next`, любых `.env`, файлов с токенами, ключами, паролями. Если что-то из этого попало — исправьте `.gitignore` и сделайте `git rm -r --cached <путь>`.

```bash
git commit -m "Первая выгрузка кода сайта"
```

Затем создать на github.com приватный репозиторий `vargov-site` (без README) и:

```bash
git remote add origin https://github.com/vargov3-spec/vargov-site.git
git push -u origin main
```

Альтернатива без командной строки: **GitHub Desktop** — Add local repository → Commit → Publish repository с галочкой **Keep this code private**.

## 4. Что делать после выгрузки

Разобраться в структуре проекта и подключить переводы. Порядок:

1. **Понять систему локализации.** Какие языки заведены сейчас, как устроены маршруты, откуда берутся тексты статей и карточек. Не угадывать — прочитать код.
2. **Добавить `vi` и `ar`** в список локалей.
3. **Маршруты** `/vi/journal/*` и `/ar/journal/*` для 22 статей.
4. **RTL для арабского**: `dir="rtl"` на корневом элементе, проверить зеркальные отступы, выравнивание, направление стрелок навигации. Список RTL-локалей есть в `meta.rtlLocales`.
5. **Переключатель языков и `hreflang`** — добавить оба языка.
6. **Карточки товаров** — проверить, все ли 8 языков подключены, недостающие взять из `integration/by-locale/`.
7. **Обновить три статьи**, где текст в репозитории свежее, чем на сайте (см. раздел 5).

Работать через pull request, не пушить в `main` напрямую. Проверка и слияние — за владельцем.

## 5. Важные решения владельца (соблюдать)

**География производства.** Фабрика в Китае — собственная, поэтому в текстах пишется «наше собственное производство» **без указания страны**. Аналогично про происхождение бренда: «за пределами домашнего рынка», а не «за пределами России».

Исключение — статья `istoriya-elementa` («История одного элемента»): там Китай назван намеренно во всех восьми языках, потому что на этом построена вся аргументация. **Не трогать.**

**Это уже исправлено в репозитории, но НЕ на сайте.** Три статьи — `fabrika`, `prototipirovanie`, `vysokoe-zhyuri` — на живом сайте содержат старые формулировки во всех языках, включая русский и английский. Обновить вместе с публикацией vi/ar, иначе репозиторий и сайт разойдутся.

**Тексты карточек.** В них нельзя называть материалы элементов (хрусталь, стекло, фарфор, керамика) — только видимые свойства и оттенки. Правила в `content/product-descriptions/PLAN.md`. Это ограничение действует для карточек товаров, но **не** для статей журнала — там материалы называть можно и нужно.

## 6. Известные вопросы (не блокируют)

- **Повтор абзаца** в русских карточках LC0321, LC0323, LC0324, LC0325, LC0326, LC0328, LC0329: один абзац стоит дважды. Английский перевод повтор убрал, остальные шесть языков воспроизвели. Рекомендация — вычистить в русском оригинале. Приоритет низкий.
- **Испанская опечатка** на живом сайте, `/es/journal/fabrika`: «América **o** Oriente Medio» → по правилу RAE должно быть «América **u** Oriente Medio».
- **Даты в `istoriya-elementa`**: элемент «создан весной 2022», но «опубликован 23 февраля 2022» — публикация раньше создания. Плюс в теле «8 декабря 2023», а в блоке ссылок «3 декабря 2023». Нужно уточнить у владельца верные даты, затем синхронизировать все восемь языков.

Полный список — `knowledge/journal-i18n-audit.md`.

## 7. Полезное про инфраструктуру

- Сайт работает на **собственном VPS в Timeweb Cloud**, IP `72.56.38.211`, nginx + Next.js. Не Vercel, не Netlify.
- Тот же сервер обслуживает `configurator.vargov.ru`.
- Деплой сейчас ручной: собрать на компьютере → скопировать на сервер. У конфигуратора уже настроена автоматика через GitHub Actions (`vargov-configurator/.github/workflows/deploy-ru-vps.yml`) — ту же схему можно применить к сайту после появления репозитория. Учтите: прямой SSH с GitHub-раннеров на VPS заблокирован фильтром, поэтому там сделан pull по HTTPS.
- Процесс Next.js в списке процессов называется `next-server (vX.Y.Z)`, а не `node` — `ps aux | grep node` его не находит.
