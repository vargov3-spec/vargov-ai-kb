# Почему `ps aux | grep node` ничего не показал

Дата: 2026-08-09. Проверено запросами к живому сайту.

## Вывод: сайт работает нормально, тревоги нет

Приложение Next.js **запущено и обслуживает запросы**. Команда его не нашла из-за особенности самого Next.js, а не из-за проблем с сервером.

## Доказательства, что приложение живо

Ключевая идея проверки: если бы процесс был мёртв, а nginx отдавал сохранённые в кэше страницы, то запрос на адрес, которого нет в кэше, упёрся бы в неработающий upstream и вернул `502 Bad Gateway`. Проверил три таких случая:

| Проверка | Результат | Что доказывает |
|---|---|---|
| Заведомо несуществующий адрес `/nesushchestvuyushchaya-stranica-diag-99137` | `404`, HTML на 29 КБ | Ответила **страница 404 самого Next.js** с полной вёрсткой сайта. У nginx своя страница 404 — она весит около 150 байт. Значит, запрос дошёл до приложения. |
| Главная с уникальным параметром `/?diag=99137` | `200` | Такой адрес не мог лежать в кэше — ответ сформирован на лету. |
| `POST /` | `405 Method Not Allowed` | Так отвечает именно Next.js на попытку отправить POST на обычную страницу. Мёртвый upstream дал бы `502`. |

Дополнительно: в ответе на несуществующий адрес стоит `cache-control: private, no-cache, no-store` — то есть ответ динамический, а не выданный из кэша.

## Почему команда его не нашла

Next.js при запуске **переименовывает свой процесс**. В списке процессов он отображается не как `node server.js`, а как `next-server (v15.x.x)`. Поэтому фильтр по слову `node` его пропускает — искомого слова в строке просто нет.

## Как убедиться самому

Любая из этих команд покажет процесс:

```bash
ps aux | grep -i next
```

```bash
ss -tlnp
```

Вторая выведет список занятых портов вместе с именами процессов — там будет виден порт (обычно 3000), на который nginx проксирует запросы, и обслуживающая его программа.

Если приложение запущено через systemd (в `/var/www/vargov/deploy/` есть папка `systemd`, значит скорее всего так и есть):

```bash
systemctl status vargov-ru
```

## Побочное наблюдение

В заголовках ответа `x-nextjs-prerender: 1` приходит **дважды**. Это значит, что заголовок добавляют одновременно и приложение, и nginx (директивой `add_header`). Дублирование безвредно, на работу сайта не влияет, но при следующей правке конфига nginx лишнюю строку можно убрать.
