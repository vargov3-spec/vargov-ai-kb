# Как выложить код сайта в GitHub (делается один раз, на основном компьютере)

Зачем: чтобы я мог вносить правки в сайт через pull request, а у вас появилась резервная копия и история изменений. Сейчас код существует в единственном экземпляре на одном компьютере — если с ним что-то случится, сайт восстанавливать будет неоткуда.

Установлено: на сервере (`/var/www/vargov/ru`) лежит только собранная версия Next.js — `server.js`, `node_modules`, `.next`. Исходников там нет, править сайт через сервер невозможно.

---

## Вариант А — через GitHub Desktop (проще, рекомендую)

Не требует командной строки.

1. Установить **GitHub Desktop**: https://desktop.github.com — войти под аккаунтом `vargov3-spec`.
2. Сначала создать файл `.gitignore` (см. раздел ниже) — это обязательно, иначе в GitHub уедут пароли и сотни мегабайт мусора.
3. В GitHub Desktop: **File → Add local repository** → указать папку с сайтом → если предложит «create a repository», согласиться.
4. Внизу слева вписать описание (например `первая выгрузка сайта`) → **Commit to main**.
5. Вверху нажать **Publish repository**:
   - имя: `vargov-site`;
   - галочка **Keep this code private** — обязательно, в коде могут быть ключи;
   - **Publish**.
6. Готово. Прислать мне название репозитория.

## Вариант Б — через командную строку

Основной компьютер под Windows, поэтому команды для **Git Bash** (устанавливается вместе с Git for Windows) или PowerShell.

```bash
cd "путь/к/папке/сайта"

# 1. Проверить, не репозиторий ли уже
git status

# 2. Если ответ «not a git repository» — создать
git init -b main

# 3. СНАЧАЛА создать .gitignore (см. ниже), только потом:
git add .
git status          # проверить: не должно быть node_modules, .next, .env

git commit -m "Первая выгрузка кода сайта"
```

Затем на github.com: **New repository** → имя `vargov-site` → **Private** → создать без README. GitHub покажет адрес, подставить его:

```bash
git remote add origin https://github.com/vargov3-spec/vargov-site.git
git push -u origin main
```

## Файл .gitignore — создать ДО первого коммита

В корне папки сайта создать файл с именем `.gitignore` (точка в начале обязательна) и таким содержимым:

```
node_modules/
.next/
out/
build/
dist/

.env
.env.*
!.env.example

*.log
.DS_Store
Thumbs.db
.vercel
next-env.d.ts
```

Что и почему исключается:

| Строка | Причина |
|---|---|
| `node_modules/` | Сотни мегабайт скачанных библиотек. Восстанавливаются командой `npm install`, хранить их не нужно. |
| `.next/`, `out/`, `build/`, `dist/` | Результаты сборки. Пересобираются из исходников. |
| `.env`, `.env.*` | **Самое важное.** Здесь пароли, ключи API, токены. Попадание в GitHub — утечка доступов. |
| `*.log` | Журналы работы, мусор. |

Если `.env` случайно уже попал в коммит — не публикуйте репозиторий, скажите мне, поправим до отправки.

## Заодно стоит решить (отдельно от переводов)

Сейчас деплой выглядит так: собрать на своём компьютере → скопировать на сервер вручную. После появления репозитория можно настроить автоматическую доставку — ровно такую же, как уже работает у конфигуратора (`vargov-configurator/.github/workflows/deploy-ru-vps.yml`): push в `main` → сборка в GitHub Actions → сервер сам забирает готовое по HTTPS. Это снимет ручную работу и риск забыть что-то выложить. Схема уже отлажена на вашей же инфраструктуре, включая обход блокировки порта 22 для GitHub-раннеров.
